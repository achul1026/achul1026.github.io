이 블로그는 글자만 있는 페이지라서 가벼울 거라고 생각했다. 확인한 적은 없었다. 그래서 배포된 사이트를 브라우저로 열어서 글 한 편을 읽을 때 실제로 몇 바이트가 오가는지 쟀다. 결과부터 적으면, 글 본문(HTML)은 압축 후 5KB가 안 되는데 웹폰트가 1.2MB였다.

## 어떻게 쟀나

- 대상: 2026년 10월 25일 시점에 배포된 `achul1026.github.io`. 한국에서 접속했고 응답은 인천 엣지(`x-served-by: cache-icn...`)에서 왔다.
- 브라우저: Claude 데스크톱 앱에 들어 있는 Chrome 152 계열 브라우저. 일반 Chrome이 아니다.
- 파일 크기는 `curl`의 `%{size_download}`와 브라우저의 Resource Timing(`encodedBodySize`)으로 봤다.
- 폰트 파일(woff2)은 Resource Timing이 크기를 0으로 줬다(캐시가 데워져 있었다). 그래서 파일 목록만 거기서 뽑고, 각 파일을 `fetch(url, {cache: 'reload'})`로 다시 받아서 바이트 수를 더했다. 브라우저가 처음 방문 때 실제로 받은 값과 정확히 같다고는 장담하지 못한다.

## HTML과 CSS는 작다

| 파일 | 원본 | gzip |
|---|---|---|
| 홈 HTML | 8,591B | 2,656B |
| JWT 글 HTML | 23,039B | 4,776B |
| `style.css` | 9,653B | 2,958B |

여기까지는 예상대로다. GitHub Pages는 `Accept-Encoding: gzip`을 보내면 gzip으로 응답했다. `br`만 보냈더니 압축 없이 원본이 왔다. 이쪽은 Brotli를 쓰지 않는 것 같은데, 문서로 확인한 건 아니고 내 요청 두 가지에서 본 것뿐이다. 같은 요청을 jsDelivr에 보내면 Brotli가 왔다(Pretendard CSS 12,493B, gzip은 13,156B).

## 폰트가 나머지를 다 차지한다

글 본문은 명조 계열인 Noto Serif KR, 나머지는 Pretendard를 쓴다. 둘 다 `unicode-range`로 잘게 나눈 조각을 필요한 만큼만 받는 방식이다. JWT 글 하나를 열었을 때의 합계는 이랬다.

| 항목 | 개수 | 바이트 |
|---|---|---|
| Pretendard woff2 조각 | 14 | 369,540 |
| Noto Serif KR woff2 조각 | 21 | 871,028 |
| 폰트 CSS 2개 (압축 후) | 2 | 58,858 |
| HTML + `style.css` (gzip) | 2 | 7,734 |
| 합계 | | 1,307,160 |

폰트 파일만 1,240,568B로 전체의 94.9%다. 조각으로 나눠 놓으면 필요한 만큼만 받으니 가볍다고 막연히 믿었는데, 한국어 글 한 편이 쓰는 글자가 흩어져 있어서 조각 35개를 거의 다 받는 셈이었다. 브라우저의 `document.fonts`로 보면 Noto Serif KR은 조각 248개 중 21~22개가 로드됐다. 파일 목록은 21개인데 로드 상태는 22개라서 한 개가 어디서 왔는지는 모른다.

폰트 CSS도 가볍지 않다. Google Fonts가 `curl`에는 472B를 줬는데 브라우저에는 압축 후 46,365B(풀면 191,042B)를 줬다. User-Agent에 따라 응답이 달랐고, 브라우저 쪽은 248개 조각 선언이 전부 들어 있었다.

## 이미지는 다른 문제다

10월 5일 글(인덱스를 걸었더니...)은 PNG 그래프 3장이 84,495B, 55,270B, 249,735B로 합쳐 389,500B다. 이 글은 폰트를 빼도 HTML 5,839B의 약 67배를 이미지가 차지한다. 가장 큰 것은 Grafana 대시보드 캡처다. PNG를 다시 압축하거나 WebP로 바꾸면 얼마나 줄지는 아직 재 보지 않았다.

## 모르는 것

- 폰트를 시스템 글꼴로 바꾸면 읽는 경험이 얼마나 달라지는지, 로딩이 얼마나 빨라지는지는 재지 않았다. 바이트만 쟀고 체감 속도나 렌더링 시간은 쟀지 않았다.
- 다른 글, 다른 브라우저, 첫 방문이 아닌 재방문에서 값이 어떻게 달라지는지 쟀지 않았다. 폰트 조각 수는 글에 쓰인 글자에 따라 달라진다.
- 모바일 회선에서의 체감은 모른다.

다음에 손볼 곳은 정해졌다. 본문 명조를 유지할지 정하고, 유지한다면 필요한 두 굵기 중 하나만 받게 할 수 있는지부터 확인한다. 그 뒤에 같은 방법으로 다시 잰다.
